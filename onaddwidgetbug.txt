Bug #1: onAddWidget() 未添加到通道路由
========================================

文件: Sample/MainWindow.cpp, 函数 onAddWidget() (第 539~610 行)

一、Bug 描述
------------

通过"添加图元"对话框在板卡上新建一个 QML 图元后，该图元
显示正常，但永远不会收到数据源推送的实时数据。

具体表现：图元内容（如 Linear、BarGraph）初始化后保持静态，
数值不动、指针不转、柱状图无变化。

二、根因
--------

数据源的值通过以下链路分发到图元：

  DataSource::valueProduced(name, value)
    → MainWindow::onValueProduced(name, value)
      → 遍历 mChannelRoutes:
          匹配 channel name → 调用 board->updateValue(objectId, value)

onAddWidget() 在创建图元后（第 606 行 board->createNewObject(info)），
没有在 mChannelRoutes 中插入对应的 {channel, objectId} 条目。

因此 onValueProduced() 永远不知道新图元的存在，不会为它调用
board->updateValue()，图元自然收不到数据。

三、修复方案
------------

方案 A：对话框加通道选择（推荐，对用户透明）
------------------------------------------------

在现有的"添加图元"对话框中增加一个 QComboBox，列出
temperature / pressure / level / flow 四个通道供用户选择。
确定后将 {用户所选通道, mNextWidgetId} 追加到 mChannelRoutes。

改动范围：
  1. 在对话框 form 中增加一行"数据通道:" + QComboBox
  2. 在 board->createNewObject(info) 之后添加:
       mChannelRoutes.append({channels[currentIdx], mNextWidgetId});

优点：用户明确知道新图元对应哪个通道，路由可控。
缺点：对话框多一个选项。

方案 B：自动轮询分配（简单，但随机）
-----------------------------------------------

在 board->createNewObject(info) 之后，统计当前 mChannelRoutes
中已有条目数，按 channels[] 轮询分配下一个通道。

  const QStringList channels = {"temperature", "pressure", "level", "flow"};
  const QString &ch = channels[mChannelRoutes.size() % channels.size()];
  mChannelRoutes.append({ch, mNextWidgetId});

优点：对话框无需改动，一行代码。
缺点：用户不知道图元被分到了哪个通道，路由不可控。

方案 C：不自动分配，由用户在"图元属性"中配置（高阶）
------------------------------------------------------------

在 QScadaObjectInfo 中增加 channelName 字段，保存到 .irp 项目文件。
onAddWidget() 时不分配路由，由后续的"属性编辑"功能设置。
项目加载时从 XML 恢复路由表。

优点：最完整，路由持久化。
缺点：需要改动实体层 + XML 序列化 + 新增属性编辑 UI，工作量较大。

四、建议
--------

当前 Demo 阶段推荐方案 A，改动最小且用户能清楚知道
新建的图元会显示哪一路数据。后续如果实现属性编辑功能，
可升级为方案 C 以支持项目持久化。

----------------

  - 添加图元入口: MainWindow::onAddWidget()    ~第 539 行
  - 通道路由定义: QList<ChannelRoute> mChannelRoutes  ~MainWindow.h 第 158 行
  - 初始化路由表: setupScadaBoard()             ~第 177~230 行
  - 加载后重建路由: onLoadProject()              ~第 490~520 行
